# layboad 제품 소개서 (Product Overview)

> **한 줄 정의**
> **layboad = PDF·이미지 교재 위에 여러 명이 실시간으로 함께 필기·공유하는, 설치 없는 온라인 과외용 웹 칠판(SaaS)입니다.**

> 이 문서는 "layboad가 어떤 제품이고, 무엇을 하며, 어떻게 동작하는가"를 설명합니다.
> 코드 레벨의 유지보수 세부(저장 위치·캐시 정책·RLS 등)는 자매 문서 [`docs/ARCHITECTURE.md`](./ARCHITECTURE.md) 를 참고하세요.
> 본문 곳곳의 `🖼 [그림 필요]` 표시는 "여기에 이런 그림이 있으면 이해가 쉽다"는 제안이며, 마지막 **부록 A**에 한 번에 정리해 두었습니다.

---

## 1. 한마디로 말하면

방장이 **PDF 교재를 브라우저에 올리면 그게 그대로 칠판(도화지)이 되고**, 학생은 **코드 하나로 입장**해 같은 화면에서 **실시간으로 함께 필기**합니다. 줌 프로그램의 화면 공유가 아니라, **모두가 같은 무한 캔버스를 동시에 그리는** 방식입니다.

핵심 차별점 세 가지:

- **교재가 곧 칠판** — 수백 페이지 PDF도 스마트 캐싱으로 바로 넘겨가며 그 위에 판서.
- **방장의 통제권** — 학생 필기를 가리거나 투명도를 조절하고, 풀이를 "단계(레이어)"로 나눠 껐다 켰다.
- **기기 자유도** — 태블릿·펜(삼성 S펜 포함)·마우스·손가락을 구분해, 펜은 필기·손가락은 페이지 넘김으로 자연스럽게 분리(팜리젝션).

🖼 **[그림 필요 #1 — 히어로 컨셉 일러스트]** PDF 문제지 위에 손글씨 풀이가 겹쳐지고, 오른쪽에 학생 2~3명의 커서/필기가 실시간으로 나타나는 모습. 제품 첫인상을 한 장으로 전달.

## 2. 누구를 위한 것인가

| 대상 | 상황 | layboad가 주는 것 |
|---|---|---|
| **1:1 · 소그룹 과외 방장** | 화상으로 수학·과학을 가르치는데 판서할 칠판이 마땅치 않음 | 교재 위 즉시 판서 + 학생 실시간 참여 |
| **학생(피교육자)** | 방장 설명을 눈으로만 따라감 | 같은 화면에 직접 풀이를 쓰고 즉시 피드백 |
| **온라인 학원·공부방** | 여러 학생 동시 수업, 진도 통제 필요 | 수업 모드로 학생 화면 고정 + 정원 관리 |

문제 정의: **"온라인 과외에서 종이 문제지에 함께 풀이를 써 내려가던 경험"을 웹에서 그대로 재현**하는 것. 기존 화이트보드 앱은 빈 캔버스 중심이라 교재 결합이 약하고, 화면 공유는 학생이 직접 못 쓴다는 한계가 있습니다.

## 3. 핵심 사용 흐름

### 3.1 방장

1. 이메일·구글·카카오로 **로그인** → **대시보드**.
2. **"새 교실 만들기"** → 입장 암호(4자 이상) 설정 → **6자리 방 코드** 자동 발급.
3. 방에 입장해 **교재(PDF/이미지) 업로드** → 배경으로 깔림.
4. 학생에게 **코드 + 암호** 전달.
5. **수업 모드**를 켜면 학생 화면이 방장 페이지를 강제로 따라옴.

### 3.2 학생

1. 랜딩 페이지에서 **초대 코드 입력** (또는 `/join/<코드>`).
2. 로그인 → **이름 + 입장 암호** 입력 → 검증 통과 시 입장.
3. 펜·손가락으로 **자기 풀이를 필기** → 방장·다른 학생 화면에 실시간 표시.

🖼 **[그림 필요 #2 — 유저 플로우 다이어그램]** 두 갈래(방장/학생) 플로우차트. `로그인 → 대시보드 → 방 생성 → 교재 업로드 → 수업` 과 `코드 입력 → 로그인 → 암호 확인 → 입장 → 필기`. 분기점(암호 오류·정원 초과·체험 만료)도 함께 표기.

## 4. 기능 상세

### 4.1 교재 배경 (PDF·이미지)

- PDF는 `pdfjs-dist`로 페이지별 이미지를 렌더해 캔버스 배경으로 사용. 이미지 파일도 지원.
- 배경 원본은 **Supabase Storage**에 저장하고, 페이지 데이터에는 **URL·페이지번호·방향·투명도 같은 메타만** 보관합니다. (배경 이미지를 필기 데이터에 통째로 넣으면 용량이 폭증해 저장 실패·지각생 빈 화면이 나므로, 로드 시점에 URL로 다시 렌더합니다.)
- **배경 투명도 조절** 가능 — 교재를 흐리게 깔고 풀이를 강조하는 용도.

### 4.2 필기 도구

`FloatingToolbar`에서 선택하는 도구들:

- **펜** — `perfect-freehand` 기반 필압/굵기 표현. 볼펜/만년필/붓 3가지 스타일.
- **형광펜** — 반투명(40%) 하이라이트.
- **도형** — 사각형·원·직선 등.
- **텍스트** — 클릭해 글자 입력.
- **영역 캡처** — 화면 일부를 드래그로 오려 이미지 객체로 복제(2배 해상도로 떠서 0.5배로 배치 → 원본 크기 유지). 캡처 이미지도 Storage로 업로드.
- **지우개** — 아래 4.3에서 상세.

모든 필기는 화면에 보이는 픽셀이 아니라 **논리 좌표(scenePoint)** 로 기록되어, 기기·줌·화면비가 달라도 배경과 필기 정렬이 어긋나지 않습니다.

### 4.3 지우개 (본인 것만·겹친 것 한 번에)

- **본인 필기만** 지웁니다(`authorName === userName`). 남의 필기·배경은 보호.
- 포인터에 닿은 **겹친 획을 한 번에** 제거.
- 모드 인식: 배경 편집 모드에선 배경 위 필기만, 수업 모드에선 현재 단계 필기만 지움.
- **마우스 우클릭 / 펜 몸통 버튼(2) / 펜 뒤꼭지 지우개(5·buttons&32)** 는 도구를 바꾸지 않고 **즉시 지우기 제스처**로 동작 — 툴 지우개와 완전히 같은 로직(`eraseAtScenePoint`)을 공유합니다.

### 4.4 팜리젝션 — 펜 vs 손가락 구분 (기술적 핵심)

과외는 태블릿 + 펜 환경이 많아, **펜은 필기 / 손가락은 페이지 넘김**으로 나누는 게 UX의 관건입니다. 문제는 삼성 S펜 같은 일부 기기가 캔버스 라이브러리 내부에서 펜을 `touch`로 넘겨줘, 펜과 손가락이 구분되지 않는다는 점이었습니다.

해결책은 **위치 상관(position correlation)**:

1. 브라우저 `window`에서는 같은 펜이 `PointerEvent(type=pen)`로 정확히 잡힙니다 → 펜의 **최신 위치·시각**을 계속 기록.
2. 캔버스가 받은 터치가 그 펜과 **같은 위치(60px)·비슷한 시각(200ms)** 이면 "그 펜의 터치"로 보고 **필기 허용**.
3. 펜 tip에서 멀리 떨어진 터치(손바닥·다른 손가락)는 자동으로 제외 → **페이지 넘김 전용**.

또한 펜을 쓰는 동안(뗀 뒤 400ms까지)엔 손 입력을 아예 무시(`useTouchSwipe`의 GRACE)해, 펜+손바닥이 함께 닿아도 페이지가 튀지 않습니다.

🖼 **[그림 필요 #3 — 팜리젝션 판별 그림]** 태블릿 위에 펜 tip(초록 원)과 손바닥(회색 큰 원)이 동시에 닿은 그림. 펜 주변 60px 반경 원 안의 터치는 "필기 O", 반경 밖 손바닥은 "무시 → 페이지 넘김"으로 화살표 표시. 판별식(거리<60px, 시간차<200ms)도 캡션에.

### 4.5 풀이 단계(Steps) 레이어

복잡한 문제를 **단계별 레이어**로 쌓아, 방장이 **눈알 버튼으로 각 단계를 껐다 켰다** 할 수 있습니다. "먼저 조건만 보여주고, 풀이 1단계 → 2단계 → 정답 순으로 공개" 같은 수업이 가능합니다. 단계는 표시 여부·투명도를 가지며, 학생 화면에도 실시간 동기화됩니다. (단계 토글은 방장 풀이 전용 — 학생 필기는 단계에 영향받지 않고 별도의 '학생 필기 통제'로만 관리됩니다.)

🖼 **[그림 필요 #4 — 레이어 스택 그림]** 교재 페이지 위에 "조건 / 풀이 1 / 풀이 2 / 정답"이 반투명 레이어로 겹쳐진 분해도. 각 레이어 옆에 눈알(표시/숨김) 아이콘.

### 4.6 학생 필기 통제

방장은 학생별로 필기 **공개 범위**(모두 공개 / 방장만 / 숨김)와 **투명도**를 조절합니다. 수업에 방해되는 낙서를 가리거나, 특정 학생 풀이만 전체에게 보여주는 식으로 활용합니다. (작성자 본인은 언제나 자기 필기를 봅니다.)

### 4.7 두 가지 모드 — 배경 편집 vs 수업

- **배경 편집 모드** — 교재(배경)와 "배경 위 고정 필기"를 다루는 준비 모드. 배경 이미지 90도 회전 등.
- **수업 모드** — 실제 수업. 켜면 학생 화면이 방장 페이지를 강제로 따라오고(진도 통제), 단계·학생 통제가 활성화됩니다.

### 4.8 실시간 동기화 + "그리는 중" 스트리밍

실시간은 **Supabase Realtime 채널**(`room:{코드}`)의 broadcast·presence로 구현됩니다. 핵심 설계는 **실시간(비영구) 신호와 영구 저장을 분리**한 것:

| 이벤트 | 방향 | 용도 | DB 저장 |
|---|---|---|---|
| `draw` | 완성된 획 | 원격 렌더 + (방장) 저장 | ✅ |
| `draw-live` | 그리는 중(50ms 간격, 같은 id 교체) | **실시간 스트리밍** | ❌ |
| `erase` | 지운 id들 | 원격 제거 | (방장) ✅ |
| `update-room-state` | 방장→학생 | 수업모드·페이지 강제 이동 | — |
| `sync-steps` / `sync-bg` / `sync-pages` | 방장→학생 | 단계·배경 투명도·PDF 메타 동기화 | — |
| presence | 전원 | 정원 계산 + 참가자 명단 | — |

`draw-live` 덕분에 상대가 선을 **긋는 도중에도 내 화면에 실시간으로** 나타나며(완성 후에야 뜨는 게 아님), 저장은 획 완성 시점에만 일어나 DB 부하를 막습니다. 같은 stroke id로 조각을 교체하므로 중간 조각이 누적되지 않습니다.

🖼 **[그림 필요 #5 — 실시간 broadcast 흐름도]** 가운데 Supabase Realtime 채널. 방장·학생 클라이언트가 `draw-live`(점선, 저장 안 함)와 `draw`(실선, DB 저장)를 주고받는 모습. 방장만 DB(room_pages/room_events)로 화살표가 이어지는 것을 강조.

### 4.9 지각 입장 catch-up

수업 도중 들어온 사람도 **기존 필기와 교재를 모두** 봐야 합니다. 입장 시 DB 스냅샷(`room_pages`)을 한 번에 불러오고, 그 **로딩 중 도착한 실시간 이벤트는 버퍼에 모아뒀다가** 로딩이 끝나면 스냅샷 위에 재적용합니다. PDF는 저장된 URL로 다시 렌더하고, 새로 추가된 PDF만 그 페이지로 이동할 때 지연 로드(lazy)합니다.

🖼 **[그림 필요 #6 — 지각 입장 시퀀스 다이어그램]** 시간축 위에: (1) 학생 입장 → (2) DB 스냅샷 요청/수신 → 이 사이에 도착한 draw 이벤트들이 "버퍼"에 쌓임 → (3) 스냅샷 렌더 → (4) 버퍼 flush 재적용 → (5) 이후 실시간 즉시 반영.

### 4.10 페이지 넘김 + 화면 자동 맞춤

- **손가락 가로 스와이프**로 이전/다음 페이지(펜 입력 중에는 무시).
- 페이지 로드·전환·기기 회전·리사이즈 때마다 `fitCanvasToView`가 **페이지 전체가 화면에 딱 들어오도록** 줌·이동을 자동 계산(레터박스). 배경이 있으면 그 페이지 기준, 없으면 A4 비율 기본 프레임(1000×1414) 기준이라 **모든 기기가 같은 시점**을 공유합니다.

🖼 **[그림 필요 #7 — 뷰포트 오토핏 그림]** 좌: 잘려 보이던 화면 / 우: 페이지 전체가 레터박스로 딱 맞게 축소된 화면. 태블릿 세로·데스크톱 가로 두 기기에서 같은 페이지가 동일하게 보이는 대비.

### 4.11 참가자 명단 · 정원

presence로 현재 접속자를 추적해, 방장 패널에 **실시간 참가자 명단**(닉네임 + 입장 시각)을 보여줍니다. 정원(요금제별 동시 학생 수)을 넘긴 **본인만** 입장이 막히며, 기존 참가자는 영향받지 않습니다.

### 4.12 단일 활성 세션(계정 도용 방지)

같은 계정을 여러 기기에서 동시에 쓰지 못하도록, 기기별 토큰으로 `profiles.active_session`을 점유하고 **자기 프로필 행을 실시간 구독**합니다. 다른 기기에서 로그인하면 토큰이 바뀌고, 기존 기기는 즉시 로그아웃됩니다.

🖼 **[그림 필요 #8 — 단일 세션 kick 시퀀스]** 기기 A 로그인(토큰 A 점유) → 기기 B 로그인(토큰 B로 덮어씀) → Realtime이 기기 A에 변경 통지 → 기기 A "다른 기기 로그인" 알림 후 강제 로그아웃.

### 4.13 앱처럼 설치(PWA)

`manifest.ts`로 홈 화면 추가를 지원. 태블릿·폰에서 "홈 화면에 추가"하면 주소창·뒤로가기가 사라진 **전체화면**으로 열려, 수업 중 실수로 뒤로가기를 누를 일이 없습니다.

## 5. 시스템 아키텍처

```
[브라우저: 방장/학생]
   Next.js 16 (App Router) + React 19
   └ Fabric.js 캔버스 · perfect-freehand · pdfjs-dist
          │  (실시간 broadcast·presence)
          ▼
   ┌─────────────── Supabase ───────────────┐
   │ Auth (이메일·구글·카카오)                 │
   │ Realtime (room:{코드} 채널)              │
   │ Postgres + RLS (rooms·pages·events·…)   │
   │ Storage (교재·캡처·리플레이 버킷)         │
   └─────────────────────────────────────────┘
          ▲
   서버 라우트(App Router) — service_role
   └ 결제(billing/*) · cron 갱신  ※ Toss 현재 보류
```

- **프론트 전면(front-heavy)** 설계: 캔버스·동기화 로직 대부분이 클라이언트에 있고, 백엔드는 Supabase(관리형 Postgres/Realtime/Storage/Auth)가 담당.
- 서버 코드(App Router 라우트)는 주로 **결제**용이며 `service_role`로 RLS를 우회.

🖼 **[그림 필요 #9 — 시스템 아키텍처 다이어그램]** 위 ASCII를 정식 박스 다이어그램으로. 클라이언트 계층(브라우저·캔버스·PDF), Supabase 4대 서비스, 서버 라우트를 구획으로 나누고 데이터 흐름 화살표 표기.

## 6. 데이터 모델

주요 테이블(전체 정의는 `db/schema.sql`):

- **profiles** — 계정. 요금제(`plan`)·상태(`status`)·체험만료(`trial_ends_at`)·구독만료(`current_period_end`)·단일세션토큰(`active_session`) 등.
- **rooms** — 교실. `code`(6자리)·`host_id`·`is_active`·`max_students`(생성 시점 요금제 기준으로 고정).
- **room_pages** — 페이지 스냅샷. 배경 메타 + 단계(steps) + 필기 JSON(전경/배경 위 필기 분리, 배경 이미지는 제외).
- **room_events** — 이벤트 로그(`add`/`erase`/`page`). 순서가 매겨져 재생·복원의 원천.
- **gift_codes** — 단건/선물 코드(`LB-XXXX-XXXX`), 사용 여부.

🖼 **[그림 필요 #10 — ER 다이어그램]** profiles(방장) 1—N rooms 1—N room_pages / room_events, gift_codes는 profiles와 사용관계. PK/FK와 핵심 컬럼만 간결히.

## 7. 저장 · 캐시 전략 (요약)

- **영구 저장**: 방장만 자동 저장(1초 debounce)하며, 학생 필기도 방장이 broadcast로 받아 자기 DB에 저장. 탭 닫힘·전환 시 안전망 저장.
- **캐시**: 방코드→UUID 매핑, 로드된 PDF 문서, 렌더된 페이지 이미지(LRU 20장), 앞뒤 ±1 페이지 프리페치, 방장 방 상태(localStorage). 세부는 `ARCHITECTURE.md`의 캐시 총정리 표 참고.
- **용량 관리**: DB+Storage 합산 사용량을 요금제 한도와 비교해, 초과 시 새 필기 저장을 중단하고 배너로 안내(실시간 수업은 계속).

## 9. 디자인 시스템 — Glass Green

투명한 유리질감(글래스모피즘) + **잎사귀 초록** 팔레트 + 물방울 느낌을 **단일 규칙**으로 정의했습니다.

- 모든 토큰·컴포넌트·장식이 `globals.css` 한 파일과 `<GlassGreen/>` **단일 프로바이더**에 모여 있습니다.
- `<GlassGreen/>`는 전역 스위치 — 붙이면 테마·떨어지는 잎사귀·물방울 터짐이 켜지고, **떼면 전부 사라집니다**.
- 배경 장식(잎/물방울)의 **위치·크기·낙하 궤적까지 CSS 규칙(nth-child + keyframes)에 저장**되어, 페이지마다 따로 붙이지 않아도 됩니다. 일정 크기 이상의 버튼(`gg-drop`)만 누를 때 물방울이 터집니다.
- 색조·투명도·라운드·낙하 속도는 `--color-leaf-*`, `--gg-*` 변수만 바꾸면 적용된 모든 페이지에 자동 반영됩니다.
- **현재 랜딩 페이지에 적용 완료**, 나머지 페이지는 배경 투명화 + `gg-*` 클래스로 opt-in 하면 됩니다(적용 위치는 별도 안내한 치트시트 참고).

🖼 **[그림 필요 #11 — 디자인 토큰 맵]** 잎사귀 색 스와치(leaf-50~800), 유리 카드/버튼(primary·glass·ghost) 예시, 물방울 터짐 상태 변화, 배경 잎 낙하 궤적을 한 장에 정리한 스타일 시트.
